# สำหรับนักวิจัยและนักพัฒนา

หน้านี้เป็นเอกสารทางเทคนิคของงานสาธิตเว็บ «การแยกนิกายในพระพุทธศาสนา» จัดทำขึ้นสำหรับผู้ที่ต้องการเข้าใจโครงสร้างภายในของโครงการ นำโค้ดไปใช้งานต่อ หรือร่วมพัฒนาโครงการนี้

งานสาธิตเว็บ: https://indapanno.github.io/buddhism/share/branching/ (ภาษารัสเซีย) และ https://indapanno.github.io/buddhism/share/branching/th.html (ภาษาไทย)
ที่มา: บทความในช่องสาธารณะ «ทำความเข้าใจพระพุทธศาสนา» บนแอปพลิเคชันข้อความแม็กซ์ (Max)

## เกี่ยวกับโครงการ

งานสาธิตเว็บนี้เป็นคู่มือแบบโต้ตอบเกี่ยวกับประวัติศาสตร์การแยกนิกายในพระพุทธศาสนา — ตั้งแต่ปรินิพพานของพระพุทธเจ้าศากยมุนีจนถึงนิกายร่วมสมัย (เถรวาท เซน เกลุก และอื่น ๆ) ผู้ใช้เดินตามแผนภูมิเหตุการณ์ทีละขั้น เริ่มจากจุดเริ่มต้นและลงลึกไปยังเหตุการณ์ย่อย หรือใช้เมนูเพื่อไปยังเหตุการณ์ใดก็ได้โดยตรง

แต่ละเหตุการณ์เป็นการ์ดแยกต่างหากพร้อมข้อมูลครบทุกด้านที่มี: ชื่อเหตุการณ์ วันที่ สถานที่ สาเหตุ ผลลัพธ์ บุคคลสำคัญ สถานะในปีปัจจุบัน ภูมิภาคที่แพร่หลายในปัจจุบัน และแหล่งที่มา สาเหตุและผลลัพธ์ถูกเน้นด้วยภาพให้เห็นว่าเป็นข้อมูลสำคัญที่สุด — เพราะเป็นคำตอบของคำถามหลักของงานสาธิตนี้ คือ «เหตุใดพระพุทธศาสนาจึงแตกแขนงเป็นนิกายต่าง ๆ»

โครงการนี้จัดทำโดยพระภิกษุที่มิใช่โปรแกรมเมอร์ ผ่านการสนทนากับผู้ช่วยปัญญาประดิษฐ์ (Claude จาก Anthropic) — ตั้งแต่การออกแบบฐานข้อมูลไปจนถึงการแก้ไขข้อผิดพลาดของโค้ดและการแปลเป็นภาษาไทย

## เทคโนโลยีที่ใช้

โครงการนี้จงใจออกแบบให้เรียบง่ายที่สุดในทางเทคนิค — ไม่มีเครื่องมือ build ไม่มีเฟรมเวิร์ก และไม่มีการพึ่งพาที่ต้องใช้ `npm install`:

- **Frontend** — HTML5, CSS3 (ใช้ CSS custom properties สำหรับธีม) และ JavaScript ล้วน (ไวยากรณ์แบบ ES5 ไม่ผ่านการแปลง) ไม่ใช้เฟรมเวิร์กใด ๆ (React, Vue ฯลฯ)
- **ข้อมูล** — ไฟล์ JSON แยกตามภาษา (`json/ru.json`, `json/th.json`) โหลดผ่าน `fetch()` ในฐานะไฟล์ภายนอก แยกจาก HTML
- **การรองรับหลายภาษา** — `js/app.js` ไม่ผูกติดกับภาษาใดภาษาหนึ่งเลย ข้อความในส่วนติดต่อผู้ใช้ ('สาเหตุ' 'เหตุการณ์ย่อย' ข้อความแจ้งเตือนข้อผิดพลาด ฯลฯ) ถูกแยกไว้ในพจนานุกรมต่างหาก `js/strings/ru.js` และ `js/strings/th.js` แต่ละไฟล์ยังระบุที่อยู่ไฟล์ JSON ของตนผ่าน `window.APP_CONFIG` ด้วย การเพิ่มภาษาใหม่จึงไม่ต้องแตะโค้ดหลัก — เพียงสร้างพจนานุกรมใหม่ หน้า HTML ใหม่ และ JSON ข้อมูลใหม่
- **ตัวเลขและการปรับให้เข้ากับท้องถิ่น** — พจนานุกรมแต่ละภาษามีฟังก์ชัน `formatNumber()` สำหรับภาษารัสเซียฟังก์ชันนี้ไม่ทำอะไร ส่วนภาษาไทยจะแปลงเลขอารบิกเป็นเลขไทย (๐–๙) ในทำนองเดียวกัน เรื่องวันที่ก็ได้รับการแก้ไข — เวอร์ชันภาษาไทยแสดงวันที่เป็นพุทธศักราช (พ.ศ.) พร้อมวันที่คริสต์ศักราชในวงเล็บเพื่อการอ้างอิง — รายละเอียดดูในหัวข้อว่าด้วยการแปลด้านล่าง
- **การนำทาง** — ผ่าน URL hash (`#event-<id>`) ซึ่งทำให้ปุ่ม 'ย้อนกลับ' ของเบราว์เซอร์ทำงานได้ฟรีโดยไม่ต้องเขียนโค้ดเพิ่ม
- **การเก็บสถานะ** — `localStorage` ของเบราว์เซอร์: การเลือกธีม การเลือกภาษา รายการเหตุการณ์ที่เคยศึกษาแล้ว (พร้อมปุ่มล้างข้อมูลในส่วนหัวของหน้า)
- **แบบอักษร** — Google Fonts: Noto Serif/Noto Sans สำหรับอักษรซีริลลิกและละติน, Noto Serif Thai/Noto Sans Thai สำหรับอักษรไทย (Noto Serif/Sans ธรรมดาไม่รองรับตัวอักษรไทย)
- **สถิติผู้เข้าชม** — GoatCounter (ฟรี เน้นความเป็นส่วนตัว โปรดทราบว่าตัวนับสาธารณะของบริการนี้แคชผลลัพธ์นานถึง ๔ ชั่วโมง และไม่นับการเข้าชมซ้ำภายในเซสชันเดียวกัน — เป็นคุณสมบัติของบริการ มิใช่ข้อผิดพลาด)
- **การโฮสต์** — GitHub Pages: การให้บริการไฟล์แบบสถิตล้วน ไม่มีแบ็กเอนด์และไม่มีตรรกะฝั่งเซิร์ฟเวอร์

แนวทางนี้มิได้เลือกโดยบังเอิญ: ในระหว่างการพัฒนาเคยทดลองใช้การแสดงผลที่ 'สวยงาม' กว่า (D3.js กับแผนภูมิรูปวงกลม) แต่พบว่าซับซ้อนเกินไปสำหรับการแก้ไขข้อผิดพลาดและการดูแลรักษาโดยบุคคลเดียวที่ไม่มีประสบการณ์เขียนโปรแกรม วิธีการปัจจุบัน — การ์ดเหตุการณ์พร้อมการนำทางแบบเจาะลึก (drill-down) — เรียบง่ายกว่าแต่ใช้งานได้จริงครบถ้วนและไม่พบข้อผิดพลาดที่ทราบ

## ขอบเขตข้อมูลปัจจุบัน

ขณะนี้ฐานข้อมูลมี **๕๕ เหตุการณ์** — ตั้งแต่ปรินิพพานของพระพุทธเจ้าจนถึงนิกายร่วมสมัยหลายแห่ง (รวมถึงเซนญี่ปุ่น เกลุกทิเบต โชเกเกาหลี จุกเลิมเวียดนาม และอื่น ๆ) แปลสมบูรณ์แล้วสองภาษา (รัสเซียและไทย) นี่เป็นเพียงส่วนหนึ่งของภาพรวมทั้งหมด: แผนภูมิเต็มรูปแบบของนิกายและความแตกแยกทางพระพุทธศาสนาในทางทฤษฎีนั้นไม่มีขอบเขตจำกัด (มีสายการสืบทอด ประเพณีวัด และนิกายย่อยท้องถิ่นที่ยังคงดำรงอยู่หลายร้อยแห่ง)

การประมาณคร่าว ๆ — ๕๕ เหตุการณ์ปัจจุบันครอบคลุมประมาณ **๓๐–๓๕%** ของปริมาณที่จำเป็นในการสะท้อนสายหลักและกิ่งก้านสำคัญที่สุด (ไม่นับรวมสายย่อยท้องถิ่นเล็ก ๆ) การประมาณนี้เป็นเพียงค่าประมาณ: แนวคิด 'ความสมบูรณ์ ๑๐๐%' ในที่นี้ไม่มีขอบเขตที่ชัดเจน

## วิธีติดตั้งสำเนาของตนเองแบบไม่มีค่าใช้จ่าย

GitHub Pages ช่วยให้ผู้สนใจสามารถติดตั้งสำเนาโครงการของตนเองได้ฟรี โดยไม่ต้องมีเซิร์ฟเวอร์:

1. ทำการ fork repository https://github.com/indapanno/buddhism มายังบัญชี GitHub ของท่าน
2. ใน fork ของท่าน ไปที่ **Settings → Pages** ในหัวข้อ **Build and deployment → Source** เลือก **Deploy from a branch** สาขา `main` โฟลเดอร์ `/ (root)`
3. หลังจากผ่านไป ๑–๒ นาที เว็บไซต์จะพร้อมใช้งานที่ `https://<ชื่อผู้ใช้ของท่าน>.github.io/buddhism/share/branching/`
4. แก้ไข `json/ru.json` (หรือ `json/th.json`) ตามความต้องการของท่าน — การแก้ไขจะเผยแพร่โดยอัตโนมัติเมื่อทำ `git push` ครั้งถัดไป

## วิธีรันในเครื่องของตนเองสำหรับการพัฒนา

จำเป็นต้องมีเซิร์ฟเวอร์ HTTP ในเครื่อง เนื่องจากเบราว์เซอร์บล็อกการเรียก `fetch()` สำหรับไฟล์ที่เปิดโดยตรง (`file://`):

```bash
git clone https://github.com/indapanno/buddhism.git
cd buddhism/share/branching
python3 -m http.server 8000
```

เปิด `http://localhost:8000/` (เวอร์ชันรัสเซีย) หรือ `http://localhost:8000/th.html` (เวอร์ชันไทย) ในเบราว์เซอร์

## แนวทางการพัฒนาต่อ

### ๑. การเพิ่มจำนวนเหตุการณ์ด้วยความช่วยเหลือของปัญญาประดิษฐ์

ฐานข้อมูลปัจจุบันทั้งหมดถูกรวบรวมผ่านการสนทนากับผู้ช่วยปัญญาประดิษฐ์ตามขั้นตอนต่อไปนี้ — สามารถทำซ้ำได้เพื่อเพิ่มเหตุการณ์ใหม่:

1. **กำหนดเหตุการณ์ต้นทาง** ค้นหาใน `ru.json` เหตุการณ์ (ตาม `id`) ที่เหตุการณ์ใหม่ควรแยกออกมา — เช่น นิกายย่อยของประเพณีที่มีอยู่แล้วซึ่งยังไม่ได้บรรยายไว้
2. **กำหนดคำถามให้ผู้ช่วยปัญญาประดิษฐ์** พร้อมคำอธิบายโครงสร้างฟิลด์ของวัตถุ (ดูโครงสร้างด้านล่าง) และขอให้ค้นหาข้อมูลที่น่าเชื่อถือเกี่ยวกับเหตุการณ์ทางประวัติศาสตร์นี้ผ่านการค้นหาเว็บ พร้อมระบุแหล่งที่มา
3. **ตรวจสอบแต่ละเหตุการณ์แยกกัน** มิใช่เป็นชุดใหญ่ — เพื่อให้สังเกตเห็นข้อผิดพลาดทางข้อเท็จจริงหรือวันที่ไม่แม่นยำได้ง่ายขึ้น ก่อนที่จะเข้าสู่ฐานข้อมูล
4. **ใส่ใจกับวันที่ที่เป็นข้อถกเถียง** ประวัติศาสตร์พระพุทธศาสนายุคต้น (หลายศตวรรษแรก) มีการกำหนดวันที่ที่แตกต่างกันหลายสิบถึงหลายร้อยปีระหว่างประเพณีต่าง ๆ (เช่น การนับแบบยาวและแบบสั้นของปรินิพพาน) กรอกฟิลด์ `достоверность_даты` อย่างซื่อสัตย์ โดยระบุถึงความแตกต่างของความเห็น มิใช่เลือกเวอร์ชันใดเวอร์ชันหนึ่งว่าถูกต้องเพียงหนึ่งเดียว
5. **เพิ่มวัตถุลงในอาร์เรย์ JSON** ตามโครงสร้างฟิลด์ (ดูด้านล่าง) พร้อม `id` ถัดไปตามลำดับและ `id_родителя` ที่ถูกต้อง
6. **ตรวจสอบความถูกต้องของ JSON** ก่อน commit:
   ```bash
   python3 -c "import json; json.load(open('json/ru.json', encoding='utf-8'))" && echo "OK"
   ```
7. Commit และ push การเปลี่ยนแปลง อย่าลืมเพิ่มเหตุการณ์เดียวกัน (ด้วย `id` และ `id_родителя` เดียวกัน แต่แปลข้อความแล้ว) ลงใน `th.json` และไฟล์ภาษาอื่น ๆ ด้วย เพื่อไม่ให้แผนภูมิของแต่ละภาษาแตกต่างกัน

**โครงสร้างของวัตถุเหตุการณ์หนึ่งรายการ:**

```json
{
  "id": 56,
  "id_родителя": 46,
  "код": "1.1.1.2.3.2.2.1.1.1",
  "название": "…",
  "тип_события": "основание_школы",
  "ветвь": "…",
  "дата": "…",
  "достоверность_даты": "…",
  "место": "…",
  "причина": "…",
  "результат": "…",
  "ключевые_фигуры": ["…"],
  "время_существования": "…",
  "статус_на_2026": "…",
  "регион_распространения_сегодня": "…",
  "число_последователей_2026": null,
  "источники": ["…"]
}
```

ฟิลด์ `примечание` ไม่บังคับ สามารถเพิ่มได้หากต้องการข้อสังเกตสำคัญ (เช่น การจัดประเภทนิกายที่เป็นข้อถกเถียง) ที่ไม่เข้ากับฟิลด์อื่น ฟิลด์ `id`, `id_родителя` และ `код` เป็นฟิลด์เชิงเทคนิคและไม่แปล ต้องเหมือนกันในทุกเวอร์ชันภาษาของ JSON เพื่อไม่ให้แผนภูมิแตกต่างกันระหว่างภาษา

### ๒. การแปลเป็นภาษาใหม่

ประสบการณ์การแปลเป็นภาษาไทยแสดงให้เห็นว่าการแปลเชิงกลไกอย่างเดียวไม่เพียงพอ — การปรับให้เข้ากับวัฒนธรรมท้องถิ่นอย่างแท้จริงมีความสำคัญ:

- **ตัวเลขและปฏิทิน** หากวัฒนธรรมเป้าหมายมีระบบวันที่ต่างออกไป (เช่น พุทธศักราชในประเทศไทย: พ.ศ. = ปีคริสต์ศักราช + ๕๔๓ และสำหรับปีก่อนคริสตกาล พ.ศ. = ๕๔๓ − ปีก่อนคริสตกาล) หรือระบบตัวเลขต่างออกไป ควรใช้ระบบเหล่านั้น มิใช่เพียงแปลข้อความ เพิ่มฟังก์ชัน `formatNumber()` ในพจนานุกรมของภาษาใหม่ (ดู `js/strings/th.js` เป็นตัวอย่าง) — โค้ดทั้งหมดจะปรับรูปแบบตามโดยอัตโนมัติ
- **คำศัพท์เฉพาะทางต้องตรวจสอบ** ชื่อบุคคลทางประวัติศาสตร์ ชื่อสถานที่ทางภูมิศาสตร์ และชื่อนิกายมักมีการเขียนที่ยึดถือกันในวรรณกรรมพุทธศาสตร์ของภาษาเป้าหมาย ซึ่งอาจแตกต่างจากการทับศัพท์เชิงกลไกอย่างชัดเจน ควรตรวจสอบผ่านการค้นหา มิใช่พึ่งพา 'สัญชาตญาณการแปล' ของผู้ช่วยปัญญาประดิษฐ์
- **การตรวจทานขั้นสุดท้ายโดยเจ้าของภาษาเป็นสิ่งจำเป็น** โดยเฉพาะในส่วนที่ซับซ้อนอย่างการทับศัพท์ชื่อทิเบตและจีน (ระบบไวลี, พินอิน) — เป็นรายละเอียดปลีกย่อยที่ผู้ช่วยปัญญาประดิษฐ์ซึ่งมิใช่เจ้าของภาษาและมิใช่ผู้เชี่ยวชาญด้านทิเบตศึกษา/จีนศึกษา อาจผิดพลาดได้
- การเพิ่มภาษาใหม่ต้องทำดังนี้: (๑) สร้าง `js/strings/<รหัสภาษา>.js` ตามแบบ `ru.js`/`th.js`; (๒) สร้าง `<รหัสภาษา>.html` ตามแบบ `th.html`; (๓) แปลและสร้าง `json/<รหัสภาษา>.json` ด้วยโครงสร้าง id/id_родителя เดียวกับ `ru.json`; (๔) เพิ่มตัวเลือกในเมนูดรอปดาวน์ภาษาในทุกหน้าภาษาที่มีอยู่; (๕) สร้าง `docs/for-researchers/<รหัสภาษา>.md`

### ๓. การปรับปรุง UI/UX — แนวคิดบางประการ

ด้านล่างนี้คือแนวทางที่ยังไม่ได้นำมาใช้ในเวอร์ชันปัจจุบัน แต่อาจเป็นที่น่าสนใจสำหรับการพัฒนาต่อไป:

- **แผนที่ภาพรวมเชิงแสดงผล** ชั้นเสริมเพิ่มเติม (เช่น แผนภูมิรูปวงกลมแบบง่ายที่ไม่มีป้ายกำกับที่โหนดภายใน มีเพียงจุดแยกกิ่ง) เป็นอีกวิธีหนึ่งในการมองภาพรวมทั้งแผนภูมิได้ชัดเจนยิ่งขึ้น พร้อมเชื่อมโยงกลับสู่หน้าเหตุการณ์หลักเมื่อคลิก
- **การค้นหาแบบเต็มข้อความ** ตามชื่อ บุคคลสำคัญ และเนื้อหาสาเหตุ/ผลลัพธ์ — มีประโยชน์เมื่อฐานข้อมูลขยายใหญ่เกินกว่าจะนำทางผ่านเมนูได้สะดวก
- **ตัวกรอง** ตามสาย (เถรวาท/มหายาน/วัชรยาน) ศตวรรษ หรือประเภทเหตุการณ์
- **รายการ 'รายการโปรด' แยกต่างหาก** ไม่ขึ้นกับรายการ 'ศึกษาแล้ว' — เพื่อให้สามารถบันทึกเหตุการณ์ที่น่าสนใจไว้กลับมาดูภายหลัง โดยไม่ปะปนกับความคืบหน้าในการศึกษา
- **ปุ่ม 'แชร์เหตุการณ์'** — คัดลอกลิงก์ตรง (`#event-<id>`) ไปยังคลิปบอร์ดด้วยการกดครั้งเดียว
- **การแปลภาษาที่เหลือให้เสร็จสมบูรณ์** — ภาษาอังกฤษและภาษาจีน — โดยรักษาโครงสร้าง JSON เดียวกัน
- **การปรับปรุงด้านการเข้าถึง** — แอตทริบิวต์ ARIA สำหรับเมนูและการ์ด การนำทางด้วยแป้นพิมพ์อย่างสมบูรณ์
- **โหมด PWA/ออฟไลน์** — ความสามารถใช้งานคู่มือได้โดยไม่ต้องเชื่อมต่ออินเทอร์เน็ตหลังการเข้าชมครั้งแรก
