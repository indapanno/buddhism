# Исследователям и разработчикам

Эта страница — техническая документация к веб-демонстрации «Ветвление буддизма». Она адресована тем, кто хочет понять, как устроен проект изнутри, взять код для собственных нужд или помочь с его развитием.

Веб-демонстрация: https://indapanno.github.io/buddhism/share/branching/ (русская версия) и https://indapanno.github.io/buddhism/share/branching/th.html (тайская версия)
Публикация-повод: канал «Разобраться в буддизме» в мессенджере Макс.

## О проекте

Веб-демонстрация — это интерактивный проводник по истории ветвления буддизма: от паринирваны Будды Шакьямуни до современных школ (тхеравада, дзен, гелуг и другие). Пользователь идёт по дереву событий шаг за шагом, начиная с корня и погружаясь в дочерние события, либо пользуется меню для прямого перехода к любому событию.

Каждое событие — это отдельная карточка со всеми доступными полями: название, дата, место, причина, результат, ключевые фигуры, статус на 2026 год, регион распространения сегодня, источники. Причина и результат выделены визуально как самая важная информация — они отвечают на главный вопрос демонстрации: «почему буддизм стал ветвиться».

Проект сделан монахом-непрограммистом в диалоге с ИИ-ассистентом (Claude, Anthropic) — от проектирования датасета до отладки кода и перевода на тайский язык.

## Технологии

Проект сознательно сделан максимально простым технологически — без сборщиков, фреймворков и зависимостей, требующих `npm install`:

- **Frontend** — чистые HTML5, CSS3 (с CSS custom properties для тем) и JavaScript (ES5-совместимый синтаксис, без транспиляции). Ни одного фреймворка (React, Vue и т.п.) не используется.
- **Данные** — JSON-файл на каждый язык (`json/ru.json`, `json/th.json`), загружается через `fetch()` как внешний файл, отдельно от HTML.
- **Многоязычность** — `js/app.js` полностью не привязан к языку. Тексты интерфейса («Причина», «Дочерние события», сообщения об ошибках и т.д.) вынесены в отдельные словари `js/strings/ru.js` и `js/strings/th.js`, каждый из которых также указывает путь к своему JSON-файлу через `window.APP_CONFIG`. Чтобы добавить новый язык, не нужно трогать основной код — только создать новый словарь, HTML-страницу и JSON с данными.
- **Числа и локализация** — у каждого языкового словаря есть функция `formatNumber()`. Для русского она ничего не делает, для тайского — конвертирует арабские цифры в тайские (๐–๙). Так же решён вопрос дат: тайская версия показывает даты в буддийском летоисчислении (พ.ศ.) с григорианской датой в скобках для сверки — подробнее см. раздел о переводе ниже.
- **Навигация** — через URL-хеш (`#event-<id>`), что даёт бесплатную поддержку кнопки «назад» браузера без единой строчки кода для этого.
- **Хранение состояния** — `localStorage` браузера: выбор темы, выбор языка, список посещённых событий (с возможностью сбросить через кнопку в шапке).
- **Шрифты** — Google Fonts: Noto Serif/Noto Sans для кириллицы и латиницы, Noto Serif Thai/Noto Sans Thai для тайской графики (обычные Noto Serif/Sans не поддерживают тайские глифы).
- **Аналитика** — GoatCounter (бесплатный, приватность-ориентированный счётчик посещений; учтите, что его публичный счётчик кэшируется до 4 часов и не считает повторные заходы в рамках одной сессии — это особенность сервиса, не баг).
- **Хостинг** — GitHub Pages: чисто статическая раздача файлов, без бэкенда и без серверной логики.

Такой подход был выбран не случайно: в процессе разработки пробовались более «эффектные» визуализации (D3.js с круговой дендрограммой), но они оказались избыточно сложными для отладки и поддержки одним человеком без опыта программирования. Текущее решение — карточка события с навигацией drill-down — проще, но полностью рабочее и без известных ошибок.

## Структура репозитория

```
share/branching/
├── index.html              — русская версия страницы
├── th.html                 — тайская версия страницы
├── css/
│   ├── style.css            — все стили, включая тёмную/светлую темы
│   └── style-th.css         — переопределение шрифтов для тайской графики
├── js/
│   ├── app.js                — вся логика: рендер карточек, навигация, меню, localStorage (не зависит от языка)
│   └── strings/
│       ├── ru.js              — тексты интерфейса и путь к данным для русской версии
│       └── th.js              — тексты интерфейса и путь к данным для тайской версии
└── json/
    ├── ru.json                — датасет событий (русские тексты)
    └── th.json                — датасет событий (тайские тексты, та же структура id/id_родителя)
```

Документация для разработчиков лежит в `docs/for-researchers/` — по одному файлу на язык (`ru.md`, `th.md`, далее `en.md`, `zh.md`).

## Текущий охват датасета

На данный момент в датасете **55 событий** — от паринирваны Будды до ряда современных школ (включая японский дзен, тибетский гелуг, корейский чоге, вьетнамский чук лам и другие), переведённых полностью на два языка (русский и тайский). Это лишь часть общей картины: полное дерево буддийских школ и расколов теоретически безгранично (сотни ныне живущих локальных линий передачи, монастырских традиций и подшкол).

Грубая, ориентировочная оценка — нынешние 55 событий покрывают **около 30–35%** от объёма, необходимого для отражения основных стволов и наиболее значимых ответвлений (без учёта самых мелких, локальных линий). Эта оценка условна: понятие «100% готовности» здесь не имеет чёткого предела.

## Как развернуть свою копию бесплатно

GitHub Pages позволяет любому желающему развернуть собственную копию проекта бесплатно, без сервера:

1. Сделайте fork репозитория https://github.com/indapanno/buddhism на свой аккаунт GitHub.
2. В своём форке зайдите в **Settings → Pages**, в разделе **Build and deployment → Source** выберите **Deploy from a branch**, ветку `main`, папку `/ (root)`.
3. Через 1–2 минуты сайт будет доступен по адресу `https://<ваш-логин>.github.io/buddhism/share/branching/`.
4. Редактируйте `json/ru.json` (или `json/th.json`) под свои нужды — правки автоматически опубликуются при следующем `git push`.

## Как запустить локально для разработки

Локальный HTTP-сервер нужен, потому что браузеры блокируют `fetch()` для файлов, открытых напрямую (`file://`):

```bash
git clone https://github.com/indapanno/buddhism.git
cd buddhism/share/branching
python3 -m http.server 8000
```

Откройте `http://localhost:8000/` (русская версия) или `http://localhost:8000/th.html` (тайская) в браузере.

## Направления доработки

### 1. Увеличение числа событий с помощью ИИ

Весь текущий датасет собран через диалог с ИИ-ассистентом по следующему протоколу — его можно повторить для добавления новых событий:

1. **Определите родительское событие.** Найдите в `ru.json` событие (по `id`), от которого должно ответвиться новое — например, ещё не описанную подшколу существующей традиции.
2. **Сформулируйте запрос ИИ-ассистенту** с описанием полей объекта (см. структуру ниже) и просьбой найти достоверную информацию об этом историческом событии через веб-поиск, с указанием источников.
3. **Проверяйте каждое событие по отдельности**, а не пачками — так проще заметить фактическую ошибку или неточную дату, прежде чем она попадёт в датасет.
4. **Обращайте внимание на спорные даты.** Ранняя история буддизма (первые века) содержит датировки, расходящиеся на десятки и сотни лет между традициями (например, длинная и короткая хронологии паринирваны). Заполняйте поле `достоверность_даты` честно, указывая на разброс мнений, а не выбирайте одну версию как единственно верную.
5. **Добавьте объект в массив JSON**, соблюдая структуру полей (см. ниже), со следующим по порядку `id` и корректным `id_родителя`.
6. **Проверьте валидность JSON** перед коммитом:
   ```bash
   python3 -c "import json; json.load(open('json/ru.json', encoding='utf-8'))" && echo "OK"
   ```
7. Закоммитьте и запушьте изменения. Не забудьте добавить то же событие (с тем же `id` и `id_родителя`, но переведённым текстом) в `th.json` и другие языковые файлы, чтобы деревья не расходились.

**Структура одного объекта-события:**

```json
{
  "id": 56,
  "id_родителя": 46,
  "код": "1.1.1.2.3.2.2.1.1.1",
  "название": "…",
  "тип_события": "основание_школы",
  "ветвь": "…",
  "дата": "…",
  "достоверность_даты": "…",
  "место": "…",
  "причина": "…",
  "результат": "…",
  "ключевые_фигуры": ["…"],
  "время_существования": "…",
  "статус_на_2026": "…",
  "регион_распространения_сегодня": "…",
  "число_последователей_2026": null,
  "источники": ["…"]
}
```

Необязательное поле `примечание` можно добавить, если требуется важная оговорка (например, спорная классификация школы), не укладывающаяся в другие поля. Поля `id`, `id_родителя` и `код` — служебные и не переводятся; они должны быть одинаковыми во всех языковых версиях JSON, чтобы дерево не расходилось между языками.

### 2. Перевод на новые языки

Опыт перевода на тайский язык показал, что механический перевод недостаточен — важна настоящая локализация:

- **Числа и календарь.** Если в целевой культуре принята другая система дат (как буддийское летоисчисление พ.ศ. в Таиланде: พ.ศ. = год н.э. + 543, а для дат до нашей эры — พ.ศ. = 543 − год до н.э.) или другая система цифр, стоит их использовать, а не просто переводить текст. Добавьте функцию `formatNumber()` в словарь нового языка (см. `js/strings/th.js` как пример) — весь код автоматически подхватит новое форматирование.
- **Терминология требует проверки.** Имена исторических фигур, географические названия и названия школ часто имеют устоявшиеся написания в буддологической литературе на целевом языке, которые могут заметно отличаться от механической транслитерации. Стоит перепроверять их через поиск, а не полагаться на «переводческую интуицию» ИИ-ассистента.
- **Финальная вычитка носителем языка обязательна**, особенно для сложных областей вроде транслитерации тибетских и китайских имён (система Уайли, пиньинь) — это тонкости, в которых ИИ-ассистент, не будучи носителем и специалистом по тибетологии/синологии, может ошибаться.
- Для добавления нового языка нужно: (1) создать `js/strings/<код-языка>.js` по образцу `ru.js`/`th.js`; (2) создать `<код-языка>.html` по образцу `th.html`; (3) перевести и создать `json/<код-языка>.json` с той же структурой id/id_родителя, что и в `ru.json`; (4) добавить пункт в выпадающий список языка на всех существующих языковых страницах; (5) создать `docs/for-researchers/<код-языка>.md`.

### 3. Совершенствование UI/UX — несколько идей

Ниже — направления, которые не были реализованы в текущей версии, но могут быть интересны для дальнейшей работы:

- **Обзорная визуализация-карта.** Дополнительный, вспомогательный слой (например, упрощённая круговая дендрограмма без подписей внутренних узлов, только с точками ветвления) — как альтернативный, более наглядный способ окинуть взглядом всё дерево целиком, с переходом в основной «эксплорер» по клику.
- **Полнотекстовый поиск** по названиям, ключевым фигурам и содержанию причин/результатов — полезно, когда датасет вырастет за пределы удобной навигации через меню.
- **Фильтры** по ветви (тхеравада/махаяна/ваджраяна), веку или типу события.
- **Отдельный список «избранное»**, независимый от списка «посещено» — чтобы можно было закладывать интересные события для возврата, не смешивая это с прогрессом изучения.
- **Кнопка «Поделиться событием»** — копирование прямой ссылки (`#event-<id>`) в буфер обмена одним нажатием.
- **Завершение остальных языковых версий** — английской и китайской — с сохранением единой структуры JSON.
- **Улучшения доступности** — ARIA-атрибуты для меню и карточек, полноценная клавиатурная навигация.
- **PWA/офлайн-режим** — возможность пользоваться проводником без подключения к интернету после первого посещения.
